# 前端界面改造设计方案

> 状态：待评审。本文针对三个痛点给出三条主线（A/B/C）的完整方案，评审通过后再进入实施。
> 涉及文件：`desktop/renderer/styles.css`、`desktop/renderer/index.html`、`desktop/renderer/src/{ui.js,main.js,state.js,config.js}`

---

## 〇、现状诊断

**痛点 1：左右栏宽度无法调节。** `.layout` 的列宽写死为 `260px / minmax(320px,1fr) / 380px`，只有"显示/隐藏"两态切换（`.sidebar-hidden` / `.evidence-hidden`），没有连续调节能力。且底部输入条 `.composer` 用固定偏移 `left:284px; right:404px` 与列宽硬耦合，一旦改列宽就会错位。

**痛点 2：滚动区域层层嵌套，滚轮被困。** 当前存在四层嵌套滚动：`.main`（页面整体）→ `.conversation`（max-height 480px）→ `.message`（max-height 360px）→ 消息内表格（inline `max-height:300px; overflow-y:auto`）。鼠标停留在任意一层上，滚轮就被该层捕获，用户必须"滚到底→挪开鼠标→继续滚外层"，体验极差。折叠状态虽然存在（`.message.collapsed`），但折叠块的滚动区域并未真正归零。

**痛点 3：信息无层级。** 所有步骤结果都以同构的 `.message` 扁平块渲染——指标卡、CSV 表格、原始 JSON、日志混在同一视觉层级，用户无法一眼分辨"结论在哪、明细在哪"。

## 一、主线 A：左右栏宽度可拖拽调节

### 方案

列宽从硬编码改为 CSS 变量驱动，两侧各加一条 4px 拖拽把手：

```css
.layout {
  display: grid;
  grid-template-columns: var(--sidebar-w) minmax(320px, 1fr) var(--evidence-w);
  /* 拖拽期间禁用过渡，避免跟手延迟 */
  transition: grid-template-columns 250ms ease;
}
.layout.resizing { transition: none; }

:root {
  --sidebar-w: 260px;
  --evidence-w: 380px;
}
```

### 细节

| 项目 | 方案 |
|---|---|
| 把手位置 | 侧栏右缘、证据面板左缘，各一条竖线，hover 高亮、拖拽时变粗 |
| 宽度范围 | 侧栏 200–420px；证据面板 300–640px；中间区最小 320px 不变 |
| 双击复位 | 双击把手恢复默认宽度（260 / 380） |
| 持久化 | 宽度存 `localStorage`，重启后恢复（仅存本机 UI 偏好，不随项目走） |
| 与折叠按钮的关系 | 保留现有折叠开关；折叠时列宽为 0，展开时恢复为记忆宽度（而非固定默认值） |
| `.composer` 联动 | 改为 `left: calc(var(--sidebar-w) + 24px); right: calc(var(--evidence-w) + 24px)`，随拖拽实时同步 |
| 证据面板 `max-width:380px` | 删除，宽度完全由 `--evidence-w` 决定 |

### 交互规则

拖拽把手只改 `--sidebar-w` / `--evidence-w` 两个 CSS 变量，`.layout` 加 `resizing` 类禁用 250ms 过渡，松开后移除。中间列由 `minmax(320px,1fr)` 自动吸收剩余空间，无需 JS 计算像素。

## 二、主线 B：「点开才滚动」单一滚动模型

### 核心原则

1. **每页只有一层滚动**：`.main` 是唯一的纵向滚动区，页面内容自然流式排布。
2. **折叠块 = 零滚动面积**：折叠时块内不产生任何 scroll 区域（`max-height:none; overflow:visible`），滚轮永远落不到它身上。
3. **展开块 = 单一受限滚动区**：只有展开态的正文才是一个有界的滚动容器，且嵌套不超过一层。
4. **滚到底不越界**：所有保留的小滚动区加 `overscroll-behavior: contain`，滚到边界即停，不传递给外层。

### 具体改造

**`.conversation`（对话区）**：去掉 `max-height:480px; overflow-y:auto`，改为自然流，让页面整体滚动。这消除了最外层的滚轮陷阱——之前鼠标停在对话区任何位置都会截获滚轮，改造后只有真正需要滚动的内容才会截获。

**`.message`（步骤结果块）**：

```css
/* 折叠态：零滚动面积（现有行为，保留） */
.message.collapsed { max-height: none; overflow: visible; }
.message.collapsed .message-body { display: none; }

/* 展开态：正文是唯一受限滚动区，嵌套最多一层 */
.message .message-body {
  max-height: calc(100vh - 300px);
  overflow-y: auto;
  overscroll-behavior: contain;
}
```

即"点一下展开，展开的正文内部才滚；不点开，整块就是一个普通段落，页面统一滚动"。

**消息内表格**：删除 inline `max-height:300px; overflow-y:auto`。表格默认展示前 N 行（见主线 C 的 L2），完整数据走 L3 模态框，模态框内部才是那个 300px+ 的滚动区。

**滚动定位**：消息渲染器里的 `scrollIntoView({behavior:'smooth', block:'end'})` 改为 `block:'nearest'`，避免页面被强行拖拽跳动——现在整页滚动，`end` 会把内容顶出视野。

**保留的小滚动区**（文件树、CSV 预览、README 等）全部加 `overscroll-behavior: contain`，滚到边界即停。

### 交互规则汇总

| 状态 | 滚动行为 |
|---|---|
| 块折叠 | 不产生任何滚动区域，滚轮直接作用于页面 |
| 块展开、内容短 | 不出现滚动条，自然流 |
| 块展开、内容长 | 正文内部单一滚动条，滚到底不越界 |

## 三、主线 C：L1/L2/L3 三级信息层级

### 层级定义

**L1 常驻头（永远可见）**：48–56px 单行条。内容 = 步骤图标 + 标题 + 状态徽章（成功/失败/运行中）+ 一行摘要（如"识别出 3 份文件，2 银行流水 1 序时账"）+ 折叠箭头。点击整条切换展开/折叠。

**L2 结构化摘要（展开后默认可见）**：指标卡片 + 前 N 行表格 + 关键结论句。高度受控，超长滚动。让用户"展开即看到结论"。

**L3 明细（按需，永不默认展开）**：完整表格 / 原始 JSON / 生成代码 / 完整日志。通过"查看完整数据"按钮进入模态框（推荐），或深层折叠区块。模态框内是独立大滚动区，关掉即回到 L2。

### 规则

- L1 永远可见；L2 展开即有、折叠即无；L3 必须显式点击才出现。
- 任何内容默认最多两级（L1+L2）。L3 只存在于"数据量超过阈值"时，小数据没有 L3。
- 展开状态记入 `state`（复用现有 `collapsedSections` 机制），切换步骤不清空。

### 逐块映射

**Agent 工作流页各消息类型**（ui.js 中对应渲染函数）：

| 消息类型 | L1（头） | L2（摘要） | L3（明细） |
|---|---|---|---|
| Detect 识别结果 | "识别完成 · 3 文件" | 文件卡片：类型/银行/时间段/置信度 | 原始识别 JSON、task.yml 全文 |
| 清洗状态（Sheet 任务） | "清洗完成 · 12/12 sheets" | 各 Sheet 状态清单（成功/失败 + 行数） | 失败 Sheet 的错误堆栈、原始数据预览 |
| Check 核查结果 | "核查完成 · 月度一致" | 指标卡（流入/流出/差额）+ 不一致月份表 | 月度明细全表、monthly_flow_check.csv |
| Match 匹配结果 | "匹配完成 · 85% 匹配率" | 匹配统计卡 + 未匹配前 20 行 | 完整 matches.csv / unmatched 表 |
| 代码生成/执行 | "生成成功 · 语法通过" | 执行摘要（输出行数、耗时） | 完整代码、stdout 日志 |
| 通用消息 | 标题 + 摘要句 | 正文 | 无 |

**证据面板（右栏）四个区块**：

| 区块 | L1 | L2 | L3 |
|---|---|---|---|
| 人工复核 | 区块标题 + 待复核数徽章 | 候选列表（当前行为，够用） | 无（现有复核编辑器已是模态式） |
| 配置确认 | 标题 + 修改状态 | YAML 编辑器（现状保留） | 无 |
| 项目文件 | 标题 + 刷新按钮 | 文件树（现状保留） | 无 |
| Git 历史 | 标题 + 最近提交一句 | 提交列表前 10 条 | 完整日志 |

**Agent 对话页**：气泡沿用现有 `.agent-msg`，工具调用结果默认折叠为一行摘要（L1），展开显示结构化结果（L2），超过 200 行的输出进 L3 模态框。

**Dashboard / 项目管理页**：统计卡即 L1，图表/表格即 L2，天然满足层级，无需改动。

### 表格行数阈值

- L2 表格默认展示 20 行，超过则显示"共 N 行，查看完整数据"按钮进入 L3 模态框。
- 模态框内置搜索/筛选输入框，替换现在的"就地滚动找数据"。

## 四、实施阶段

**Phase 1 — 布局与滚动（主线 A + B）**：styles.css 全面改列宽变量、单一滚动模型、`overscroll-behavior`；index.html 加两条把手元素；main.js 加拖拽逻辑与宽度持久化；`.composer` 联动改造。此阶段完成后痛点 1、2 即解决，视觉无大改。

**Phase 2 — 层级化消息（主线 C）**：ui.js 各消息渲染函数改为 L1/L2/L3 结构；新增通用模态框组件（`showDetailModal(title, content)`）；`scrollIntoView` 改 `nearest`。此阶段完成后痛点 3 解决。

**Phase 3 — 打磨**：拖拽把手视觉、过渡动画微调、全部展开/折叠按钮、宽度记忆的边界情况（窗口缩小到比列宽还窄时的降级）。

每阶段单独验证、单独可回滚（git 提交点），不一次性大改。

## 六、待确认问题

1. **列宽范围**：侧栏 200–420px、证据面板 300–640px 是否合适？默认值维持 260/380？
2. **宽度持久化**：是否接受 localStorage 记忆宽度？是否需要"重置布局"按钮？
3. **过渡动画**：现有 250ms 列宽过渡是否保留（拖拽时禁用、折叠/展开时保留）？
4. **L2 默认行数**：20 行还是 50 行？
5. **L3 载体**：模态框 vs 深层展开——方案倾向模态框（理由：页面已是单滚动模型，模态框提供独立大滚动区，且带搜索更符合"找数据"场景）。
6. **全部展开/折叠**：消息区是否需要一键全部展开/折叠按钮？

评审确认后，按 Phase 1 → 2 → 3 顺序实施。
